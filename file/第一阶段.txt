【第 1 周：以太坊底层机制与本地环境】
核心目标：不写复杂的 Java 代码，重点搞定理论，并在本地跑通一个测试网。

- Day 1-2：账户与交易模型（理论）
  - EOA vs 合约账户：搞懂为什么 EOA（外部账户）有私钥，而合约账户没有；为什么向合约地址转账会触发代码执行。
  - Nonce（防重放机制）：为什么以太坊要用 Nonce？如果用户连着发两笔交易，Nonce 是怎么递增的？如果一笔卡住了，后面的交易会怎样？（答案：会被阻塞，直到前一笔完成）。
  - EIP-1559 Gas 机制：现在的 Gas 是怎么算的？Base Fee（基础费，被销毁）和 Priority Fee（小费，给矿工/验证者）的区别。

- Day 3-4：交易生命周期（理论）
  - 一笔交易从钱包签名到上链，经历了什么？
  - Pending（待处理）：进内存池（Mempool）。
  - Success（成功）：状态变更，发出 Event Log。
  - Revert（失败/回滚）：状态全部撤销，但 Gas 费照扣。

- Day 5-7：环境搭建与实操
  - 本地节点：安装 Foundry（里面包含 Anvil，比 Hardhat 启动更快，适合后端调试）。
  - 部署合约：打开 Remix IDE，写一个极简的 ERC-20 合约（或者直接用 OpenZeppelin 的模板），在 Anvil 本地节点上部署。
  - 实操交互：用 MetaMask 连上本地节点，给自己转点钱，发一笔转账，去浏览器看交易详情，观察 Nonce、Gas 消耗和状态变化。

【第 2 周：Web3j 深度开发（读与解析）】
核心目标：用 Java 写代码，把链上的数据“抠”出来。这是 CEX 充值监听器的雏形。

- Day 1-2：Web3j 基础接入
  - 在 Java 项目中引入 web3j 依赖。
  - 连接节点：用 Web3j.build(new HttpService("RPC_URL")) 连接 Infura 或本地 Anvil。
  - 基础查询：查 ETH 余额、查 ERC-20 代币余额、查当前区块高度。

- Day 3-4：区块与事件解析（重点）
  - 分页拉取 Event Log：调用 eth_getLogs。由于 RPC 节点有返回大小限制，必须学会用 fromBlock 和 toBlock 分页拉取。
  - WebSocket 订阅：用 Web3j 建立 WebSocket 连接，实时订阅 newHeads（新块）和 logs（合约事件）。对比 HTTP 轮询，体会长连接的优势。
  - 解析 ERC-20 的 Transfer 事件：拿到 Log 后，怎么通过 ABI 把 data 字段解码成 from、to、amount。

- Day 5-7：内部交易（Internal Tx）与异常解析（难点）
  - 什么是内部交易：用户 A 调用合约 B，合约 B 给用户 C 转了 10 ETH。这笔 ETH 转账不会产生单独的 Transaction Hash，只会记录在 Receipt 的 internalTransactions 里。
  - 实操：如何通过 eth_getTransactionReceipt 拿到交易回执？如何追溯这笔内部转账？
  - 阶段产出：写一个 Java 服务，输入一个区块高度，能把该区块里所有的 ERC-20 转账解析出来并打印。

【第 3 周：Web3j 深度开发（写与发交易）】
核心目标：用 Java 构造、签名、广播交易，处理交易卡住等异常。这是 CEX 提币网关的雏形。

- Day 1-2：构建交易与离线签名
  - Nonce 管理：从链上获取当前地址的 Nonce，并保证并发发交易时 Nonce 不冲突。
  - Gas 估算：调用 eth_estimateGas。如果余额不足或合约 Revert，估算会报错，代码里要捕获。
  - 离线签名：私钥绝对不能传到节点！学会用 Web3j 在本地用私钥对 RawTransaction 签名（signTransaction）。

- Day 3-4：广播与状态追踪
  - 广播签名后的交易（eth_sendRawTransaction）。
  - 状态追踪：交易发出后是 Pending，怎么用代码一直轮询查 Receipt 直到它 Success 或 Fail？

- Day 5-7：进阶：交易替换（加速）与异常捕获
  - 替换机制（Replace-by-fee）：如果一笔交易在网络拥堵时卡住了（一直 Pending），你如何用同一个 Nonce，提高 Gas Price，再发一笔“自己转给自己”的空交易来覆盖它？
  - Revert 异常捕获：如果交易失败，Receipt 里的 status 是 0x0。如何通过重放交易（eth_call）来获取具体的 Revert 原因（比如 Insufficient balance）？
  - 阶段产出：写一个 Java 服务，实现：本地离线签名构建一笔 ERC-20 转账 -> 广播 -> 追踪直到成功；如果卡住，能自动提高 Gas 重新广播。

2. 准备好测试网水龙头：去 Sepolia 测试网领一点免费的测试 ETH，或者直接用 Anvil 本地节点自己造币，不用花钱。
3. 代码比理论重要：第 2 周和第 3 周，每天必须敲代码。尤其是离线签名和内部交易解析，这是重要两个技术点。
