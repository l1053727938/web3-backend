### 0.2 数据库结构

确认以下变更已执行（`sql/schema.sql` 中有完整 DDL）：

```sql
-- 用户业务
CREATE TABLE IF NOT EXISTS `user` (...);
ALTER TABLE deposit_wallet ADD COLUMN derivation_index INT NULL AFTER user_id;
ALTER TABLE deposit_wallet ADD UNIQUE KEY uk_chain_user (chain_id, wallet_type, user_id);
```

### 0.3 依赖

- `pom.xml` 使用 `spring-boot-starter-kafka`（**不能只引 `spring-kafka`**，Boot 4 的自动配置在独立模块里）

## 1. 准备测试数据

### 1.1 平台代收负债账户

消费者需要 `web3.deposit.consumer.platform-liability-account-id` 指向的账户（默认 900101）。

```bash
docker exec mysql8 mysql -uroot -p123456 -N -e "
USE web3_backend;
SELECT id, account_type, currency, available FROM account WHERE id = 900101;"
```

不存在则插入：

```sql
INSERT INTO `account` (id, user_id, account_type, currency, available, frozen, version)
VALUES (900101, 900000001, 'PLATFORM', 'USDT', 0, 0, 0);
```

> `account_type='PLATFORM'` 是关键：平台负债允许为负，否则充值分录会被余额校验拦住。

### 1.2 注册一个用户（充值归属用）

启动应用后（见第 2 步）调用：

```bash
curl -X POST http://127.0.0.1:18080/api/user/register \
  -H "Content-Type: application/json" \
  -d '{"username":"drill_user"}'
```

记下返回的 `userId`（例如 1）与充值地址。

> 用户 SPOT 账户不需要提前创建：消费者首次入账时会通过
> `LedgerAccountService.ensureAccount` 幂等开户。

## 2. 启动应用（Kafka 通道）

### 2.1 IDE 运行

VM options / 环境变量：

```
WEB3_WS_ENABLED=false
WEB3_WITHDRAW_ENABLED=false
WEB3_DEPOSIT_ENABLED=false
```

Program arguments：

```
--server.port=18080
```

> `WEB3_DEPOSIT_ENABLED=false` 只关闭“链上事件 → 充值记录”的路由服务；
> Kafka 消费者与 Outbox 投递器仍然工作，演练用 SQL 注入消息。

### 2.2 命令行运行（没有 Maven 时可用 IDE 编译产物）

```bash
java -cp "target/classes;..." com.ray.web3.Web3BackendApplication \
  --server.port=18080 \
  --web3.websocket.enabled=false \
  --web3.withdraw.enabled=false \
  --web3.deposit.enabled=false
```

### 2.3 健康检查与 lag 指标

```bash
curl -s http://127.0.0.1:18080/actuator/health

curl -s http://127.0.0.1:18080/actuator/prometheus | grep kafka_consumer_lag
# kafka_consumer_lag{application="web3-backend",group="web3-outbox"} 0.0
```

指标出现且为 0，说明消费者已连上 Kafka 并有提交位点。

### 5.3 观察

```bash
docker exec mysql8 mysql -uroot -p123456 -N -e "
USE web3_backend;
SELECT biz_no, status, retry_count, next_retry_at
FROM outbox_message WHERE biz_no LIKE 'DRILL%' ORDER BY id;"
```

Kafka 停机时：

- 消息保持 `status=NEW`，`retry_count` 会随投递失败递增；
- 注意日志里 `KafkaTemplate.send()` 会阻塞约 60s（等 metadata），
  所以 `retry_count` 不会立刻变化，这是正常现象。

## 6. 重启 Kafka

```bash
docker start kafka

for i in $(seq 1 30); do
  (echo > /dev/tcp/127.0.0.1/9092) 2>/dev/null && { echo "kafka up"; break; }
  ping -n 2 127.0.0.1 >/dev/null 2>&1
done
```

等待投递器把 outbox 发出去、消费者处理：

```bash
for i in $(seq 1 30); do
  sent=$(docker exec mysql8 mysql -uroot -p123456 -N -e "
    USE web3_backend;
    SELECT COUNT(*) FROM outbox_message WHERE biz_no LIKE 'DRILL%' AND status='SENT';" | tr -d '\r')
  consumed=$(docker exec mysql8 mysql -uroot -p123456 -N -e "
    USE web3_backend;
    SELECT COUNT(*) FROM consumer_biz WHERE biz_no LIKE 'DRILL%';" | tr -d '\r')
  echo "poll $i: sent=$sent consumed=$consumed"
  [ "$sent" = "5" ] && [ "$consumed" = "5" ] && break
  ping -n 6 127.0.0.1 >/dev/null 2>&1
done
```

## 7. 验收

```bash
docker exec mysql8 mysql -uroot -p123456 -N -e "
USE web3_backend;

SELECT 'deposit_drill', COUNT(*) FROM deposit_record WHERE deposit_no LIKE 'DRILL%'
UNION ALL SELECT 'consumer_drill', COUNT(*) FROM consumer_biz WHERE biz_no LIKE 'DRILL%'
UNION ALL SELECT 'ledger_deposit_drill', COUNT(*) FROM ledger_entry WHERE biz_type='DEPOSIT' AND biz_no LIKE 'DRILL%'
UNION ALL SELECT 'outbox_sent_drill', COUNT(*) FROM outbox_message WHERE biz_no LIKE 'DRILL%' AND status='SENT';

-- 重复落账应为 0 组
SELECT biz_no, COUNT(*) c FROM ledger_entry
WHERE biz_type='DEPOSIT' AND biz_no LIKE 'DRILL%'
GROUP BY biz_no HAVING c > 1;

-- 余额：5 × 10 = +50
SELECT user_id, available FROM account WHERE user_id=1 AND account_type='SPOT' AND currency='USDT';
SELECT id, available FROM account WHERE id=900101;"
```

本次实际结果：

| 项目 | 数值 |
|---|---|
| deposit_record DRILL | 5 |
| consumer_biz DRILL | 5 |
| ledger DEPOSIT DRILL | 5 |
| outbox SENT DRILL | 5（若做过重放会多 1 条） |
| 重复分组 | 空 |
| 用户余额 | +50 USDT |
| 平台负债 | -50 USDT |
| lag | 0.0 |

## 8. 可选：验证重复投递幂等

在 Kafka 正常运行时，再插入一条同 `bizNo` 的 outbox 消息：

```sql
INSERT INTO outbox_message (biz_type, biz_no, partition_key, payload, status, retry_count)
VALUES ('DEPOSIT','DRILL2','1','{"depositNo":"DRILL2","chainId":31337,"contractAddress":"0x5fbdb2315678afecb367f032d93f642f64180aa3","currency":"USDT","userId":"1","amount":"10"}','NEW',0);
```

等待投递后：

- `outbox_message` 中 DRILL2 有 2 条 SENT；
- `consumer_biz` 仍然只有 1 条 DRILL2；
- 账本 `DEPOSIT` 仍然只有 1 组 DRILL2；
- 用户余额不再增加。

说明“至少一次投递 + 消费端幂等”生效。

## 9. 清理（重复演练前执行）

> 清理不会回滚已入账余额；如果要完全重来，请连同余额一起处理，
> 或换一个新的单号前缀（DRILL2_1、DRILL2_2 …）。

```sql
USE web3_backend;
DELETE lp FROM ledger_posting lp
  JOIN ledger_entry le ON le.id = lp.entry_id
  WHERE le.biz_no LIKE 'DRILL%';
DELETE FROM ledger_entry WHERE biz_no LIKE 'DRILL%';
DELETE FROM consumer_biz WHERE biz_no LIKE 'DRILL%';
DELETE FROM outbox_message WHERE biz_no LIKE 'DRILL%';
DELETE FROM deposit_record WHERE deposit_no LIKE 'DRILL%';
```

## 10. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动报 `required a bean of type KafkaTemplate` | 只引了 `spring-kafka` | 改 `spring-boot-starter-kafka` |
| 启动报 `expected single matching bean but found 2: web3j,wsWeb3j` | WebSocket 默认开启 | `--web3.websocket.enabled=false` |
| 消费者日志 `用户账户不存在且开户失败` | 旧代码先 SELECT 后开户，REPEATABLE READ 快照看不到新账户 | 已修复：先 `ensureAccount` 再查询 |
| 重启后失败消息不再重投、账本缺一笔 | 默认错误处理器重试 10 次后提交 offset 跳过 | 已修复：`KafkaConsumerErrorConfig` 无限退避 + `ackAfterHandle=false` |
| 停 Kafka 后 outbox 的 `retry_count` 很久不变 | `KafkaTemplate.send()` 等 metadata 阻塞约 60s | 正常；后续改为事务外发送 |
| `docker exec kafka /opt/kafka/bin/...` 路径报错 | Git Bash 把 `/opt` 转成了 Windows 路径 | 加 `MSYS_NO_PATHCONV=1` 或用 `sh -c` |
| 重复演练时 consumed=0 | 单号重复被 `consumer_biz`/`uk_biz` 幂等挡住 | 换单号前缀，或先执行第 9 步清理 |
